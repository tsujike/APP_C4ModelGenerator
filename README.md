# Mermarium(マーマリウム)

図をテキストで書き、ブラウザ上のホワイトボードで**ズームすると詳しさのレベルが切り替わる**形で閲覧するビューワーです。名前は Mermaid + aquarium の造語で、「人魚(Mermaid)が泳ぐ水槽」を意味します。

2つのモードがあります。

- **Mermaidモード** — 任意のMermaid記法の図を `%%L1`〜`%%L8` のマーカーでレベル別に登録し、ズーム(または L1〜L8 ボタン)で切り替えて見ます。同じテーマを「概略 → 詳細」の8段階で並べたいときに使います。
- **C4モード** — C4モデル(Context / Containers / Components / Code の4階層でソフトウェアアーキテクチャを表現する手法)をMermaid C4記法のサブセット+拡張で書くと、L1〜L4 が1つのモデルから自動生成されます。

> リポジトリ名・フォルダ名は歴史的経緯から `APP_C4ModelGenerator` / `APP_C4-Model-Whiteboard-Viewer` のままです(アプリ名のみ Mermarium に変更しました)。

## 概要

- **セマンティックズーム**が核機能です。地図アプリで縮尺を上げると国→都市→街区と表示が変わるように、図をズームインすると閾値を跨いだところで **Context図(L1) → Container図(L2) → Component図(L3) → Code図(L4)** へと描画レベルが自動的に切り替わります。ズームアウトすると逆順に戻ります。
- ズーム切替の瞬間、カーソル直下(またはビューポート中心)にあったノードが、切替後も同じ画面位置に来るようカメラを補正します(アンカー保存)。「あるシステムに向かってズームインすると、その中身がその場で展開される」体験を実現します。
- 画面左のエディタ(CodeMirror 6)にテキストを入力すると、約300ms後に自動で再解析・再描画されます。パン/ズーム位置は再描画後も維持されます。
- 解析エラー・警告は行番号付きでエディタ下部のパネルに表示され、クリックすると該当行にジャンプします。
- ソースはブラウザのlocalStorageに自動保存され、次回起動時に復元されます。組込サンプル(「インターネットバンキング」「ECサイト」)をメニューから読み込めます。
- 現在の表示レベルの図をSVG/PNG(2倍解像度)でエクスポートできます。
- 描画キャンバスにはOSSの[Excalidraw](https://excalidraw.com/)を使用し、手描き風ホワイトボードの見た目で表示します(閲覧専用。図の直接編集は不可。編集は常にテキスト経由)。レイアウトは[elkjs](https://github.com/kieler/elkjs)による自動階層レイアウトです。
- サーバー不要でビルド成果物は静的ファイルのみですが、Excalidrawの手描き風フォント(Excalifont)は実行時に `esm.sh` から取得されるため、完全オフライン環境では代替フォントで表示されます。

詳しい要件・設計は `docs/` 配下を参照してください。

- `docs/01_要件定義書.md` — 何を作るか(要件・受入基準)
- `docs/02_アーキテクチャ設計書.md` — どう作るか(DSL仕様・データモデル・射影/LODアルゴリズム)
- `docs/03_実装フェーズ計画.md` — フェーズ分割と完了条件
- `docs/04_実装指示書.md` — タスク分解と実装エージェント向けの作業原則
- `docs/PROGRESS.md` — 進捗チェックリストと申し送り

## 起動方法

Node.js(npm)が使える環境で、リポジトリのルートディレクトリで以下を実行します。

```bash
npm install     # 依存関係のインストール(初回、およびpackage.json変更後は必ず実行)
npm run dev     # 開発サーバー起動(http://localhost:5173 などで表示される)
npm test        # vitestによるユニットテスト実行
npm run build   # 型チェック(tsc)+ 静的ビルド(dist/ に出力)
npm run lint    # ESLint + Prettierチェック
npm run preview # npm run build 後、成果物(dist/)をローカルで確認
```

`npm run build` の成果物(`dist/`)はサーバー不要の静的ファイル一式です。任意の静的サーバー(例: `npx serve dist`)や `npm run preview` で配信できます。

## Mermaidモードの書き方

最小のコピペ例です(`%%L1` と `%%L2` の2レベルだけ)。

```
%%L1
flowchart LR
  A[利用者] --> B[システム]

%%L2
flowchart LR
  A[利用者] --> B[Webサーバー]
  B --> C[DB]
```

### レベルマーカーの規則

- マーカーは**その行だけ**で書きます。`%%L1: 名前` や `%%L1 詳細` はマーカーとして扱われず通常のコメントになります(FR-7.2)。この書き方をするとそのレベルの図が登録されないため、`%%L1` が他に1行も無いときだけ警告が出ます。逆に `%%L1` をきちんと書いたうえで `%% L1=宣言 / L2=実態` のような凡例コメントを添えるのは自由で、警告は出ません。
- 前後の空白と大文字小文字は問いません(`%%L1` / `%% L1` / `%%l1` はすべて同じ)。
- 本文はマーカー行の次の行から、次のマーカー行の直前までです。
- マーカーが1つでもあればMermaidモード、1つも無ければC4モードになります(排他)。
- レベルを切り替えてもカメラの位置と倍率は維持されます(C4モードのようなアンカー保存はしません)。
- 同じレベルのマーカーが複数あるときは**最初の1つが勝ち**、2つ目以降は警告にして無視されます。最初のマーカーより前の非空行、および本文が空のマーカーも警告になります。ただし最初のマーカーより前の `%%` コメント行は警告になりません(文書の冒頭に凡例やメモを書けます)。
- Mermaidの文法エラーは**そのレベルだけ**空表示になり、他のレベルはそのまま表示されます。
- マーカーが1つも無いのに `flowchart` などで始まっているソースには「レベルマーカーがありません」という案内が出ます。ただし `classDiagram` はC4モードのL4入力でもあるため、この案内の対象外です(FR-7.8)。

### レベルに名前を付ける

レベルの名前は、Mermaid frontmatterの `title:` で付けます。

```
%%L1
---
title: 応募者から見た流れ
---
flowchart LR
  A["応募する"] --> B["書類選考を受ける"]
```

この `title:` はキャンバス上に見出しとして描かれます。`%%L1: 応募者から見た流れ` という書き方は使えません。

`---` は**マーカーの次の行**に置いてください。これはMermaid本体の規則で、`---` の前にコメント行が1行でもあるとfrontmatterと認識されず、そのレベル全体が `Parse error on line 1: ---title: ...` で失敗します。コメントを書きたいときは frontmatter の後ろ(`---` の下)に置きます。

### 軸の意味を宣言する(`%% MODE:`)

`%% MODE: zoom` のように書くと、L1→L8という軸そのものが何を意味するかを宣言できます。ソースの先頭に1行置くのが標準です(`%%` で始まる行なので「マーカーより前の行」警告は出ません)。

| 値           | 意味                         | ツールバー表示     |
| ------------ | ---------------------------- | ------------------ |
| `zoom`(既定) | L1→L8 で詳細度が上がる       | 軸: ズーム(詳細度) |
| `views`      | L1→L8 が別々の視点の並び     | 軸: ビュー(視点)   |
| `reader`     | L1→L8 で読者(対象者)が変わる | 軸: 読者(対象者)   |

**表示だけで、動作は変わりません**(`views` を選んでもズーム連動のレベル切替はそのまま働きます)。省略時は `zoom` になります。未知の値は警告のうえ `zoom` 扱いになります。`MODE` 行が複数あるときは最初の1つが勝ち、2つ目以降は警告になります。

### プロファイル(レベル体系の使い回し)

軸の意味(`%% MODE:`)と各レベルの名前(frontmatterの `title:`)の組み合わせを、このアプリでは「プロファイル」と呼びます。Mermariumにプロファイルを登録・保存する機能はなく、あくまで上記の書き方の規約です。C4モードは、事実上「軸はズーム(詳細度)、レベル名はContext/Containers/Components/Code」という1つのC4プロファイルだと捉えられます。組込サンプルの「プロファイル例(採用プロセス/ビュー軸)」は、C4以外の題材(採用プロセス)に `MODE: views` とfrontmatter titleを組み合わせた見本で、サンプルメニューから読み込めます。

## Mermaidモードの記法対応状況

Mermaidモードには**2つの変換経路**があり、経路によって本家Mermaidとの見た目の忠実度が異なります。どちらの経路になるかは図の種類で自動的に決まり、利用者が選択する設定はありません。

- **ネイティブ変換経路** — `flowchart`(`subgraph`無し)・`sequenceDiagram`・`stateDiagram-v2`・`erDiagram` などが対象です。Mermaidにはレイアウトの計算だけをさせ、その結果をExcalidrawのネイティブ要素(rectangle/ellipse/diamond/arrow等)として描き直します。手描き風の見た目になり、SVG/PNG出力もベクタのまま維持されますが、Excalidrawが持たない表現は失われます。
- **ラスタ画像フォールバック経路** — `subgraph` を含む `flowchart` と `classDiagram` が対象です。Mermaid自身が描いたSVGを1枚の画像としてホワイトボードに貼り付けます。形状もタイトルも本家どおり忠実ですが、画像であるため拡大すると粗くなり、Excalidrawの手描き風にはなりません。

### ネイティブ変換経路で失われる表現

| 記法                              | 本家Mermaidの表示      | Mermariumのネイティブ変換経路 |
| --------------------------------- | ---------------------- | ----------------------------- |
| `A[テキスト]`                     | 長方形                 | 長方形(そのまま)              |
| `A(テキスト)`                     | 角丸長方形             | 角丸長方形(そのまま)          |
| `A([テキスト])`                   | スタジアム(両端が半円) | 角丸長方形で**近似**          |
| `A[[テキスト]]`                   | サブルーチン(二重枠)   | **長方形**(二重枠は失われる)  |
| `A[(テキスト)]`                   | シリンダ(DB記号)       | **長方形**                    |
| `A((テキスト))`                   | 円                     | 楕円(そのまま)                |
| `A(((テキスト)))`                 | 二重円                 | 楕円2枚(そのまま)             |
| `A>テキスト]`                     | 非対称(旗形)           | **長方形**                    |
| `A{テキスト}`                     | 菱形                   | 菱形(そのまま)                |
| `A{{テキスト}}`                   | 六角形                 | **長方形**                    |
| `A[/テキスト/]` / `A[\テキスト\]` | 平行四辺形             | **長方形**                    |
| `A[/テキスト\]` / `A[\テキスト/]` | 台形                   | **長方形**                    |

Excalidrawが持つ閉じた図形は長方形・楕円・菱形の3種類だけなので、上表の「近似」「長方形」への丸めはネイティブ変換経路の原理的な限界です。形状を忠実に出したい図は `subgraph` を使ってラスタ画像経路に載せる回避策があります。長方形に丸められた場合は画面下部のパネルに警告が表示されます。

### 対応しているもの

`classDef` / `class` / `style` によるノードの色指定(塗り色・線色・線幅)は両経路で反映されます。ラベル内の `<br/>`(および `<br>`・`<br />`)は両経路で改行として表示されます。frontmatter(`---` で囲んだ `title:`)は両経路で図の上にタイトルとして表示されます。`%%L1`〜`%%L8` のマーカーにより、1つのソースに最大8枚の図をレベル別に登録できます(マーカーの無いレベルは何も表示しません)。

### Mermariumが解釈しないもの

マーカー行(`%%L1`〜`%%L8`)より前に書かれた行、同じ `%%Ln` の重複、本体が空のレベルは、いずれも画面下部のパネルに警告として表示されます。それ以外のMermaid記法の解釈は `@excalidraw/mermaid-to-excalidraw` とmermaid本体に委ねているため、本家Mermaidが解釈できる記法は基本的にそのまま書けます。

## ファイルにリンク(外部エディタ連携)

> **対応ブラウザは Chrome / Edge のみです**(File System Access APIを使用。Firefox / Safariでは非対応で、ボタンは無効表示になります)。

VSCode等の外部エディタで編集しているファイルを、保存するたびに自動で画面へ反映させる機能です。既存の「保存」「開く」ボタン(その場限りのファイルI/Oで、読み込んだ後はファイルとの関係を覚えません)とは別系統で、こちらは選んだファイルへの参照を保持し続け、外部での保存を継続的に監視します。

想定ワークフロー:

1. ツールバーの「ファイル:」グループにある**「ファイルにリンク」**ボタンを押します。
2. ネイティブのファイル選択ダイアログが開くので、VSCodeで編集したい`.txt`/`.md`/`.mmd`/`.mermaid`ファイル(「すべてのファイル」からも選択可)を選びます。現在のソースを破棄してよいかの確認が出ます。
3. 選んだファイルの内容がエディタに読み込まれ、タイトルもファイル名(拡張子除く)になります。
4. そのままVSCode等でファイルを開き、編集して**保存**します。アプリ側は1秒間隔でファイルの更新を確認しており、保存後すぐに画面の図が自動で再解析・再描画されます(タブがバックグラウンドの間は確認を止めます)。
5. リンク中はアプリのエディタは**読み取り専用**になり、直接編集できません。編集は常にVSCode側で行ってください(アプリ側で編集しても、次に外部ファイルが保存された時点で上書きされて消えてしまうため)。
6. 終了するときは**「リンク解除」**を押します。編集可能な状態に戻ります。解除してもファイルへの参照は覚えているので、次回は「再リンク: ファイル名」ボタンから1クリックで同じファイルへ戻れます(ブラウザの仕様上、アクセス許可の再確認のためこのクリックは必要です。起動直後に自動で読み込みに行くことはしません)。

書き戻し(アプリ→ファイル)は行いません。あくまでファイル→アプリの一方向の反映です。ファイルが見つからない・読み込めなくなった場合は自動的にリンクが解除され、初期状態に戻ります。

## 記法リファレンス

入力はMermaid C4記法のサブセット+本アプリの拡張です。ソーステキストは `C4Context` / `C4Container` / `C4Component` / `classDiagram` の4種類のブロックから構成され、ブロックは行頭のキーワードで始まり、次のブロック開始行またはファイル末尾までが本体です(インデント自由、空行と `%%` コメント行は無視。ただし `%% code-of:` は指令として解釈)。未対応の文は「警告」としてその行を無視し、解析できた部分だけで描画を継続します。実装の正は `src/parser/parseC4Block.ts` / `src/parser/parseClassBlock.ts` です。

### C4Context / C4Container / C4Component ブロックの文法

引数は `(` `)` 内のカンマ区切り。各引数は `"..."` 引用符付き文字列または裸の識別子(引用符内のカンマは区切りとみなしません)。`$tag=...` 形式の名前付き引数は無視されます(警告なし)。

| 文                                                                     | 意味                                                                                           | 備考                                                                        |
| ---------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| `Person(alias, label, ?descr)`                                         | 人物ノード                                                                                     |                                                                             |
| `Person_Ext(alias, label, ?descr)`                                     | 外部の人物ノード                                                                               | 塗りが灰色になる                                                            |
| `System(alias, label, ?descr)`                                         | システムノード                                                                                 |                                                                             |
| `System_Ext(...)`                                                      | 外部システム                                                                                   |                                                                             |
| `SystemDb(...)` / `SystemDb_Ext(...)`                                  | DB variantのシステム                                                                           | シリンダー近似で描画                                                        |
| `SystemQueue(...)` / `SystemQueue_Ext(...)`                            | キュー variantのシステム                                                                       |                                                                             |
| `Container(alias, label, ?tech, ?descr)`                               | コンテナノード                                                                                 | tech引数あり(第3引数)                                                       |
| `Container_Ext(...)` / `ContainerDb(...)` / `ContainerQueue(...)` など | External/Db/Queueの組合せ                                                                      | Container/Component系は全組合せ対応                                         |
| `Component(alias, label, ?tech, ?descr)`                               | コンポーネントノード                                                                           |                                                                             |
| `Component_Ext(...)` / `ComponentDb(...)` / `ComponentQueue(...)` など | 同上                                                                                           |                                                                             |
| `System_Boundary(alias, label) { ... }`                                | C4Containerブロック内で使用。`alias`が一致するContextのSystemに、内側のContainer群を結び付ける | `{`は宣言行末尾/単独行どちらも可。閉じ忘れはブロック終端で暗黙クローズ+警告 |
| `Container_Boundary(alias, label) { ... }`                             | C4Componentブロック内で使用。`alias`が一致するContainerにComponent群を結び付ける               | 同上                                                                        |
| `Enterprise_Boundary(alias, label) { ... }`                            | C4Contextブロック内の視覚的グループ化(破線枠)。内側のPerson/Systemを囲む                       | エッジ射影の対象にならない                                                  |
| `Rel(from, to, label, ?tech)`                                          | 有向エッジ                                                                                     | `from`/`to`はグローバルなalias参照(レベルをまたいでも可)                    |
| `BiRel(from, to, label, ?tech)`                                        | 双方向エッジ                                                                                   |                                                                             |
| `Rel_U` / `Rel_D` / `Rel_L` / `Rel_R` / `Rel_Up` などの方向付きRel     | `Rel`と同義                                                                                    | 方向ヒントは無視(警告なし)                                                  |
| `title ...`                                                            | 無視                                                                                           | 警告なし                                                                    |
| `UpdateRelStyle` / `UpdateElementStyle` / `UpdateLayoutConfig`         | 無視                                                                                           | 警告なし                                                                    |
| 上記以外の非空行                                                       | 「未対応の文」として警告し、その行を無視                                                       |                                                                             |

`Person`/`System`/`Container`/`Component` の基底語は `_Ext`(外部)サフィックスと `Db`/`Queue`(variant)サフィックスの組合せを一律に解釈します(例: `ContainerDb_Ext` も解釈可能)。

### classDiagram ブロックの文法(Code層)

Mermaidにはコード階層(L4)の標準記法が無いため、`classDiagram` ブロック+直前行の指令コメント `%% code-of: <componentAlias>` で対応するComponentに結び付けます(指令が無い/参照先が見つからない場合はブロック全体を警告付きで無視)。

| 文                                                                          | 意味                                                                          |
| --------------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| `class Name { ... }`(複数行可)                                              | クラスノード。ボディの各行のうち `(` を含む行はmethod、それ以外はfield        |
| `class Name`                                                                | 空のクラス(ボディ無し)                                                        |
| `A --> B` / `A --\|> B` / `A *-- B` / `A o-- B` / `A ..> B`(`: label` 任意) | クラス間のエッジ。矢印種別は描画上すべて実線矢印(継承 `--\|>` のみ白抜き三角) |
| `<<interface>>` 等の他の記法                                                | 警告なしで無視                                                                |

### 階層の結び付けルール(要約)

- `C4Context` の要素が最上位(roots)になります。ソース中に必ず1つ必要です(0個ならエラー、2個目以降は無視)。
- `C4Container` ブロックの `System_Boundary(alias, ...)` は、`alias` が一致するContextのSystemの子として、内側のContainer群を結び付けます(Boundary外の要素は警告で無視)。
- `C4Component` ブロックの `Container_Boundary(alias, ...)` も同様にContainerへ結び付けます。
- `classDiagram` は直前の `%% code-of: <componentAlias>` でComponentへ結び付けます。
- alias はソース全体でグローバルに一意です(重複はエラー、初出を採用)。
- 深いレベルの定義が無いノードはそのレベルでも箱のまま表示されます(例: L3が未定義のContainerは、L3表示でも展開されず葉ノードのまま)。

サンプルの完全な入力例は `src/samples/internet-banking.ts` / `src/samples/ec-site.ts` を参照してください(アプリの「サンプル」メニューからも読み込めます)。

## 閾値のカスタマイズ

セマンティックズームの閾値・ヒステリシス係数は `src/constants.ts` の `LOD_ZOOM_THRESHOLDS` / `LOD_HYSTERESIS_FACTOR` で一元管理しています。

```ts
// src/constants.ts
export const LOD_ZOOM_THRESHOLDS = [0.75, 1.5, 3.0] as const;
export const LOD_HYSTERESIS_FACTOR = 0.9;
```

- `LOD_ZOOM_THRESHOLDS` は正規化ズーム値 `s`(= 現在のExcalidrawズーム倍率 ÷ 起動直後にL2をFit表示した時点のズーム倍率。`src/camera/camera.ts` が算出)に対する、L1→L2 / L2→L3 / L3→L4 の各境界です。既定値は要件定義書FR-5.1の表(L1: `s < 0.75`、L2: `0.75 ≤ s < 1.5`、L3: `1.5 ≤ s < 3.0`、L4: `3.0 ≤ s`)と一致します。配列の要素数は3固定(4レベル間の3つの境界)で、値を変更すればAUTOモードでの切替タイミングが変わります。
- `LOD_HYSTERESIS_FACTOR` は「ズームアウトで1段階下のレベルへ戻る」際に適用する係数です。上昇方向(ズームイン)は閾値到達で即座に遷移しますが、下降方向(ズームアウト)は「現在レベルの下側閾値 × この係数」を下回るまで遷移しません(境界付近でのちらつき防止。詳細規則は `docs/02_アーキテクチャ設計書.md` §8.2)。値を1に近づけるほどヒステリシス幅は狭くなり、0に近づけるほど広くなります(0.9=下側10%の余裕)。
- 判定ロジック本体は `src/camera/lod.ts` の純関数 `nextLevel(current, s)` です。閾値・係数を変更した場合は `npm test`(`tests/camera/lod.test.ts`)で境界値の挙動を確認できます。
