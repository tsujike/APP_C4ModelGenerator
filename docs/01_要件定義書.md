## 1. 目的と背景

C4モデル(Context / Containers / Components / Code の4階層でソフトウェアアーキテクチャを表現する手法)を、**ブラウザ上のホワイトボードのように閲覧できるビューワー**を作る。

最大の特徴は**セマンティックズーム**である。地図アプリで縮尺を上げると国→都市→街区と表示が変わるように、本アプリでは図をズームインしていくと、閾値を跨いだところで **Context図 → Container図 → Component図 → Code図** へと描画レベルが切り替わる。C4モデルの「粒度の階層」を、ズーム操作という直感的なインタラクションに写像することが本アプリの存在意義である。

入力はテキスト(Mermaid C4記法のスーパーセット、詳細は `docs/02_アーキテクチャ設計書.md` §5)。ソースコードを貼り付けるエディタ領域と、結果を表示するビューワー領域を持つ。

## 2. スコープ

### やること
- Mermaid C4記法テキストの入力・解析・SVG描画
- ズーム操作による4階層のセマンティックズーム切替
- パン/ズーム(マウスホイール・ドラッグ)、レベル手動固定
- 解析エラー・警告の表示
- ソースのlocalStorage保存、SVG/PNGエクスポート

### やらないこと(明示的にスコープ外)
- サーバーサイド処理・アカウント・共有URL・共同編集
- 図のマウスによる直接編集(ノードのドラッグ配置等)。編集は常にテキスト経由
- Mermaid記法の完全互換(§5の対応表に載る文法のみ。未対応文は警告付きで無視)
- モバイル・タッチ最適化(動けばよい。最適化はしない)
- i18n(UIは日本語固定)

## 3. 想定ユーザーとユースケース

- ソフトウェアアーキテクト/開発者。自システムのC4モデルをテキストで管理しており、階層を行き来しながら俯瞰・詳細確認したい。
- UC-1: 手元のMermaid C4テキストを貼り付けて図を確認する
- UC-2: ズームイン/アウトで階層を行き来し、システム全体像とコンポーネント詳細を往復する
- UC-3: 特定レベルに固定してスクリーンショット/SVGを資料に使う
- UC-4: テキストを編集しながらライブプレビューで図を整える

## 4. 画面構成

```
+--------------------------------------------------------------+
| ツールバー: [ファイル: ファイルを選択 履歴▼ (リンク解除)] [レベル: L1 L2 L3 L4 L5 L6 L7 L8 |AUTO] [Fit] |
|            [ズーム率 120%] [SVG出力] [PNG出力]                 |
+--------------------+-----------------------------------------+
|                    |                                         |
|  エディタペイン      |   ビューワーペイン(Excalidrawホワイトボード) |
|  (テキスト入力)     |   - パン/ズーム可能                      |
|                    |   - 現在レベルをバッジ表示                |
+--------------------+                                         |
|  エラー/警告パネル   |                                         |
+--------------------+-----------------------------------------+
```

- エディタとビューワーの境界はドラッグでリサイズ可能(スプリッター)。
- エラー/警告パネルはエディタ下部。0件時は折りたたみ。

## 5. 機能要件

### FR-1 テキスト入力(エディタ)
- FR-1.1 複数ブロック(C4Context / C4Container / C4Component / classDiagram)を含む1つのソーステキストを編集できる。
- FR-1.2 入力後、300msのデバウンスで自動的に再解析・再描画する。
- FR-1.3 再描画時、カメラ位置(パン/ズーム状態)は維持する。
- FR-1.4 ソースはlocalStorageに自動保存し、次回起動時に復元する。
- FR-1.5 (廃止) サンプル読込メニューは post-v1.0 で廃止した(ツールバーの「サンプル▼」自体を削除。Kenny指示)。組込サンプル「インターネットバンキング」自体は削除しておらず、`loadPersistedSource` が localStorage に保存済みソースを見つけられなかった場合(初回起動時等)の既定表示としてのみ残っている(FR-1.4参照)。

### FR-2 解析とエラー処理
- FR-2.1 解析結果は統一モデル(4階層ツリー+関連エッジ)に変換される。
- FR-2.2 文法エラー・整合性エラー(未定義エイリアス参照等)は行番号付きでエラーパネルに列挙する。
- FR-2.3 エラーが一部にあっても、解析できた部分だけで描画を継続する(全消えさせない)。直前の正常描画を維持しつつエラーを表示する方式でもよい。
- FR-2.4 未対応のMermaid文は「警告」として報告し、その行は無視して続行する。

### FR-3 描画(ビューワー)
- FR-3.1 C4標準の配色・意味論で描画する(Person/System/Container/Component/DB/Queue/External/Boundary。詳細は設計書§7)。描画キャンバスにはOSSのExcalidrawを用い、手描き風ホワイトボードの見た目とする。シリンダー・人物等の形状は基本図形の組合せによる近似でよい。
- FR-3.5 ビューワーは閲覧専用とする(ExcalidrawのviewModeを使用。図の直接編集は§2のとおりスコープ外)。
- FR-3.2 レイアウトは自動(elkjsによる階層レイアウト)。手動配置はしない。
- FR-3.3 エッジはラベル・技術注記付き矢印で描画する。
- FR-3.4 ノードには名前(太字)、[技術]、説明文(折返し)を表示する。

### FR-4 パン/ズーム
- FR-4.1 パン/ズーム操作はExcalidraw標準に従う(Ctrl/Cmd+ホイールまたはピンチでカーソル位置中心のズーム、ホイール/ドラッグでパン)。独自のジェスチャ実装はしない。
- FR-4.2 (FR-4.1に統合)
- FR-4.3 Fitボタンで現レベルの図全体が収まるようにカメラをリセットする。
- FR-4.4 ズーム率はツールバーに%表示する。

### FR-5 セマンティックズーム(本アプリの核)
- FR-5.1 連続ズーム値 s に対し、以下の既定閾値で描画レベルを自動決定する(AUTOモード)。**L5〜L8はMermaidモード専用の追加レベルであり(FR-7.9)、C4モードは従来どおりL1〜L4の4段階のまま、AUTO判定もL4で頭打ちになる(s が 4.5 以上になってもL4を維持する)。**

  | 描画レベル | 図 | s の範囲(既定) |
  |---|---|---|
  | L1 | Context | s < 0.75 |
  | L2 | Containers | 0.75 ≤ s < 1.5 |
  | L3 | Components | 1.5 ≤ s < 3.0 |
  | L4 | Code(C4モードはここが上限) | 3.0 ≤ s(C4モード) / 3.0 ≤ s < 4.5(Mermaidモード) |
  | L5 | Mermaidモードのみ(FR-7.9) | 4.5 ≤ s < 6.75 |
  | L6 | Mermaidモードのみ(FR-7.9) | 6.75 ≤ s < 10.0 |
  | L7 | Mermaidモードのみ(FR-7.9) | 10.0 ≤ s < 15.0 |
  | L8 | Mermaidモードのみ(FR-7.9) | 15.0 ≤ s |

  先頭3段(L1〜L3)の閾値は変更していない。閾値は定数モジュールで一元管理し、変更可能にする。
- FR-5.2 閾値にはヒステリシスを設け、境界付近でのちらつき(レベルの往復)を防ぐ。上昇方向は閾値到達で即遷移、下降方向は閾値の90%を下回ったときに遷移する(詳細規則は設計書§8.2が正)。
- FR-5.3 レベル切替は即時のシーン差し替えとする(要素とカメラ補正を同時に適用し、中間状態を見せない)。クロスフェード等の遷移演出は要件としない。
- FR-5.4 **アンカー保存**: 切替の瞬間、マウスカーソル直下(ホイール以外起因ならビューポート中心)にあったノードが、切替後レイアウトでも同じ画面位置に来るようカメラを補正する。「あるシステムに向かってズームインしたら、そのシステムの中身が同じ場所に展開される」体験を実現する。
- FR-5.5 レベルを手動固定できる(固定中はズームしても切り替わらない)。AUTOで自動切替に戻る。固定できる範囲はC4モードで L1〜L4、Mermaidモードで L1〜L8(FR-7.9)。
- FR-5.6 現在の描画レベルをツールバーとビューワー内バッジに常時表示する。
- FR-5.7 深いレベルのデータが無い部分は、あるものだけ展開する(例: Container図がZシステムに定義されていなければ、L2でもZはL1の箱のまま表示)。
- FR-5.8 エッジは表示レベルに射影する: 非表示の深い要素へのエッジは、表示中の祖先ノードに付け替え、重複は集約する(規則は設計書§6)。

### FR-6 エクスポート
- FR-6.1 現在の表示レベルの図全体をSVGファイルとしてダウンロードできる。
- FR-6.2 同様にPNG(2x解像度)でダウンロードできる。

### FR-7 Mermaidモード(post-v1.0の追加要望)
v1.0公開後にユーザー(指揮者)から追加された要望「Mermaid記法も対応したい。レベルによって、登録したMermaidに表示が変わるだけでよく、C4モデルとの連携は不要」に対応する任意機能。C4モードとは**排他**であり、C4モード(FR-1〜FR-6)の挙動は一切変えない。

- FR-7.1 ソース中に `%%L1`〜`%%L8` のレベルマーカー行を書くと、その行以降・次のマーカー行までの記述を、そのレベルに登録された任意のMermaidソースとして扱う。マーカーが1つでもあればMermaidモード、1つも無ければ従来のC4モードとする。
- FR-7.2 マーカーはMermaidのコメント記法(`%%`)をそのまま使う。前後の空白・大文字小文字は問わない(`%%L1` / `%% L1` / `%%l1`)。マーカー行に他の文字が続く場合は通常のコメントとみなし、マーカーとしては扱わない。
- FR-7.3 表示レベルが切り替わると、そのレベルに登録されたMermaid図へ表示全体を差し替える。C4モードのようなノード単位の対応関係は持たないため、レベル切替時のアンカー保存(FR-5.4)は行わず、カメラは切替前の位置・倍率を維持する。
- FR-7.4 未登録のレベルは何も表示しない(空表示)。8レベル全部を登録する必要はない。
- FR-7.5 同じレベルのマーカーが複数ある場合は最初の1つを採用し、2つ目以降は警告にして無視する。最初のマーカーより前の非空行、および本文が空のマーカーも警告にする(警告の表示先はFR-2.4のIssuesパネル)。ただし**最初のマーカーより前にある `%%` コメント行は警告しない**。文書の冒頭にレベル体系の凡例をコメントで書くのは通常の使い方であり、コメントはMermaidから見てももともと無視される行のため「無視します」と伝える意味がないから(Kennyの実文書で誤検知したため追加)。
- FR-7.6 Mermaidの文法エラーは該当レベルのマーカー行を指す解析エラーとして表示し、そのレベルは空表示とする(他のレベルの表示は継続する)。
- FR-7.7 描画は従来どおりExcalidrawが行う(Mermaidはレイアウト計算にのみ用いる)。ただし変換ライブラリがネイティブ要素化に対応しない図(`subgraph` を含む `flowchart`、`classDiagram` 等)は1枚のラスタ画像として表示される。この画像フォールバックは許容する。
- FR-7.8 レベルマーカーが1つも無く、かつ先頭の有効行がMermaidの図種キーワード(`flowchart` / `sequenceDiagram` など)で始まるソースは、C4モードのエラーに加えて「レベルマーカーがありません」という案内を該当行へのエラーとして表示する。素のMermaidをそのまま貼った場合にFR-7.1のマーカーの書き忘れへ誘導するためのもので、モード判定自体(FR-7.1)は変えない。`classDiagram` はC4モードのL4入力(§5.4)でもあるため、この案内の対象外とする。
- FR-7.9 L5〜L8はMermaidモードに限り追加で使用できる(FR-5.1参照)。C4モードはL1〜L4のまま変わらない(C4モデルはContext/Containers/Components/Codeの4層で定義されるため、5層目以降の意味を定義できない)。C4モード中はツールバーのL5〜L8ボタンを無効表示にする。
- FR-7.10 `%% MODE: zoom` / `views` / `reader` の1行で、「L1→L8という軸そのものが何を意味するか」を宣言できる(zoom=詳細度が上がる、views=別々の視点の並び、reader=読者(対象者)が変わる)。省略時は `zoom` とする。未知の値は警告のうえ `zoom` として扱う。複数ある場合は最初の1つを採用し、2つ目以降は警告にする(FR-7.5と同じ方針)。最初のレベルマーカーより前に書かれた `%% MODE:` 行は、FR-7.5の「マーカーより前の非空行」警告の対象外とする。**この宣言はツールバーへの表示のみに使い、レベル切替やズーム連動の挙動は一切変えない**(Kenny決定。挙動を変えるかどうかは実際に使われてから判断する)。C4モードでは宣言を解釈せず、表示も出さない。
- FR-7.11 `%%L1: 名前` のように、マーカー行に文字が続く行を検出した場合は「マーカーとして扱わない」旨の警告を出す(FR-7.2の挙動自体は変えず、分かりにくい失敗を可視化するだけ)。ただし**警告を出すのは、その行が指しているレベルに正規のマーカーが1行も無い場合に限る**。`%% L1=宣言 / L2=実態` のような凡例コメントや `%% L3の凡例: 赤=是正前` のような説明コメントは、`%%L1`〜`%%L3` が別行にきちんと書かれていれば何も壊れていないため警告しない(Kennyの実文書で誤検知したため追加)。

### FR-8 ファイルにリンク(post-v1.0の追加要望)
外部エディタ(VSCode等)でソースファイルを編集し、保存するたびに本アプリの表示へ自動反映したいという要望に対応する任意機能。**post-v1.0で、旧来の「保存」「開く」ボタン(その場限りのファイルI/O。ソースを`.txt`としてダウンロードする「保存」を含む)自体を廃止し、本機能へ一本化した(Kenny指示)。「サンプル▼」メニューも同時に廃止している(FR-1.5参照)。** SVG/PNGエクスポート(FR-6.1/FR-6.2)は本改訂の対象外であり、そのまま残っている。

- FR-8.1 ツールバーの「ファイル:」グループに「ファイルを選択」ボタン(旧「ファイルにリンク」ボタンの改称)を設ける。押すと、File System Access API対応ブラウザ(Chrome / Edge)ではネイティブのファイル選択ダイアログが開き、選んだファイルへ「リンク」する(以後FR-8.3のポーリング監視対象になる)。非対応ブラウザではFR-8.7のとおり1回限りの読み込みにフォールバックする。読み込み前に既存と同じ破棄確認(`confirm()`)を行い、読み込んだ内容をエディタに反映して、タイトルをそのファイル名(拡張子除く)にする。
- FR-8.2 ピッカーが受け付ける拡張子は `.txt` `.md` `.mmd` `.mermaid` とする。「すべてのファイル」も選べる。
- FR-8.3 リンク中は、リンク先ファイルの更新日時とサイズを1秒間隔でポーリングし、いずれかが変化したら内容を読み直してエディタへ反映する(以後の再解析・再描画は既存のライブ編集経路(FR-1.2)にそのまま乗る)。タブが非表示の間はポーリングを行わない。
- FR-8.4 リンク中はエディタを読み取り専用にする。外部エディタでの編集を正とし、アプリ側での編集がポーリングによる読み直しで消えてしまう混乱を防ぐため。「リンク解除」ボタン(リンク中のみ表示される独立したボタン)を押すと編集可能に戻る。
- FR-8.5 「リンク解除」を押しても、FR-8.9の履歴からはそのファイルを取り除かない(次回も履歴から1クリックで戻れる)。ただしポーリング監視がファイルの消失(見つからない・読み込めない)を検知した場合は、そのファイルへの参照を履歴からも取り除き、未リンクの初期状態に戻す。
- FR-8.6 リンク先ファイルへの参照はブラウザに永続化し、次回起動時にFR-8.9の「履歴」メニューの1件として復元する。起動時に自動で読みに行くことはしない(ブラウザの権限モデル上、アクセス許可の再確認にはユーザー操作が必要なため)。旧仕様にあった「再リンク: ファイル名」という専用ボタンは廃止し、履歴メニューがその役割を引き継いだ。
- FR-8.7 「ファイルを選択」ボタン自体はFile System Access API非対応ブラウザ(Firefox / Safari等)でも無効化しない。非対応ブラウザで押した場合は、従来の `<input type="file">` によるその場限りの1回読み込みにフォールバックする(選んだファイルの内容はエディタに反映されるが、以後の監視も履歴への登録も行わない)。「履歴」メニューは非対応ブラウザでは常に空になるため無効化する。NFR-2の対応ブラウザ(Chrome / Edge / Firefox)のうちFirefoxは、自動反映と履歴機能のみ非対応となる(その場限りの読み込み自体は使える)。
- FR-8.8 本機能は片方向(ファイル→アプリ)のみとする。アプリ側からリンク先ファイルへの書き戻しは行わない。
- FR-8.9 ツールバーの「ファイル:」グループに「履歴▼」メニューを設ける。過去にリンクしたことのあるファイルを、最終利用日時が新しい順に最大10件(`FILE_HISTORY_MAX`)まで保持・表示する。同一ファイル(File System Access APIの `isSameEntry()` で判定)を重ねてリンクしても履歴には重複登録せず、既存の1件の最終利用日時を更新して先頭に繰り上げる。**表示できるのはファイル名と最終利用日時(`YYYY-MM-DD HH:mm`)のみで、`D:\...\foo.txt` のようなフルパスは表示できない**。これはブラウザの仕様上の制約であり、File System Access APIは `FileSystemFileHandle` から絶対パス・フォルダ構成を一切開示しない設計になっているため、本アプリ側で回避する手段が無い。メニューから1件選ぶと、そのファイルへ改めてリンクする(FR-8.1と同じ経路)。ポーリング監視がファイルの消失を検知した場合は、そのファイルを履歴からも取り除く(FR-8.5)。

## 6. 非機能要件

| ID | 要件 |
|---|---|
| NFR-1 | サーバー不要。ビルド成果物は静的ファイルのみで、ローカル静的サーバーで動作する。外部CDNに依存しない(全依存をバンドル) |
| NFR-2 | 対応ブラウザ: 最新版の Chrome / Edge / Firefox |
| NFR-3 | 性能: 総ノード200・エッジ300規模で、解析+全レベルレイアウト再計算が1秒以内、パン/ズーム操作は60fps近傍で追従 |
| NFR-4 | TypeScript strict。パーサ・モデル・射影ロジックはユニットテスト(vitest)で担保 |
| NFR-5 | 依存は最小限(@excalidraw/excalidraw、react/react-dom(Excalidrawのホストとしてのみ)、elkjs、CodeMirror 6、Vite、vitest。post-v1.0のFR-7で @excalidraw/mermaid-to-excalidraw を追加。これは @excalidraw/excalidraw が元々依存している同一バージョンを明示宣言しただけで、依存ツリーは増えていない)。アプリ自体のUIにはUIフレームワークを使わない |

## 7. 受入基準(最終検証で確認する項目)

1. 初期表示の組込サンプル「インターネットバンキング」(localStorageに保存済みソースが無い場合の既定表示。FR-1.5参照)で、L1→L4までズームインで順に切り替わり、ズームアウトで逆順に戻る(C4モードの受入基準。C4モードはL1〜L4の4段階のまま変わらない。L5〜L8はMermaidモード専用のためこの基準の対象外。FR-7.9参照)。
2. FR-5.4 のアンカー保存が体感できる(APIコンテナへズームインするとその場でコンポーネントが展開される)。
3. ソースの1行を壊すと行番号付きエラーが出て、直すと復帰する。
4. リロード後も編集内容が復元される。
5. SVG/PNGエクスポートが成功し、内容が画面表示と一致する。
6. `npm test` が全緑、`npm run build` が成功する。
7. (FR-8、Chrome / Edge限定)「ファイルを選択」でテキストファイルを選ぶとエディタに読み込まれ、リンク中は編集不可になる。リンク中に外部エディタ(VSCode等)でそのファイルを保存すると、1秒程度で表示に反映される。「リンク解除」で編集可能に戻る。同じファイルを再度選んでも「履歴」に重複して増えず、リロード後も履歴にファイル名と最終利用日時が残っており、そこから選ぶと再びリンクできる。
