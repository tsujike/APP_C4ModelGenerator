# 実装指示書 — 実装エージェント(Sonnet)向け

版 1.0 / 2026-07-18。あなた(実装エージェント)はこの指示書に従ってタスク単位で実装する。仕様の正は `docs/01_要件定義書.md`、設計の正は `docs/02_アーキテクチャ設計書.md`。本書と矛盾したらその2つを優先し、矛盾を PROGRESS.md に記録すること。

## 1. 作業原則(全タスク共通)

- **スコープ厳守**: タスクの「やること」だけをやる。頼まれていないリファクタリング・周辺整理・機能追加・将来対応の抽象化はしない。1回限りの処理にヘルパーは作らない(3回書いてから共通化)。
- **防御的コードは境界のみ**: 検証はシステム境界(ユーザー入力=DSLテキスト、localStorage読出し)でだけ行う。内部モジュール間は型を信頼し、起こり得ないシナリオのエラー処理を書かない。
- **完了条件を客観的に確認してから完了報告**: テスト実行・ブラウザ実表示など証拠を確認する。「たぶん動く」で完了にしない。テストが赤のままタスクを閉じない。
- **報告は結論から**: 何ができたか→根拠(テスト結果等)→残課題、の順で簡潔に。
- 判断に迷う仕様の曖昧さを見つけたら、勝手に仕様を発明せず、最も単純な解釈で実装して PROGRESS.md の「申し送り」に記録する。

## 2. 進め方と PROGRESS.md

- タスクは番号順に実施(並列可のものは明記)。1タスク=1コミット以上、コミットメッセージは `T2-1: elkjsレイアウト実装` 形式。
- `docs/PROGRESS.md` を T0-1 で作成し、全タスクのチェックリスト+「申し送り」節を持たせる:

```markdown
# PROGRESS
## チェックリスト
- [ ] T0-1 ...
...
## 申し送り
- (日付) 内容
```

## 3. タスク分解

### Phase 0

**T0-1 プロジェクト初期化**
- 目的: ビルド・テスト・整形が回る足場を作る。
- やること: Vite(vanilla-ts)初期化、tsconfig strict、vitest、ESLint+Prettier、`npm run dev/build/test/lint` 整備。`index.html` に §画面構成(要件§4)の空レイアウト(CSS Grid)。`src/constants.ts` に閾値・色定数(設計書§7.2, FR-5.1 の値)。`docs/PROGRESS.md` 作成。
- やらないこと: スプリッター、実描画、CI設定。
- 完了条件: `npm run dev` で4領域の骨格表示。`npm test` 緑(ダミー1件)。`npm run build` 成功。

- やらないこと: classDiagram、モデル構築、描画。
- 完了条件: テスト緑。設計書§5.4のソースが error 0 でASTになる。

**T1-2 classDiagramパーサ**
- 目的: Code層の入力を扱う。
- やること: `parser/parseClassBlock.ts`。設計書§5.3 のサブセット+`%% code-of:` 指令の関連付け情報をASTに含める。ユニットテスト。
- やらないこと: Mermaid classDiagram の完全対応(ジェネリクス・可視性記号の意味解釈等は不要)。
- 完了条件: テスト緑。class本体のfield/method分類、5種の矢印が解釈される。

**T1-3 統一モデル構築**

- 完了条件: テスト緑。サンプルのC4Modelスナップショットに4レベル全てが含まれ、issues が意図どおり。

## 4. コーディング規約

- TypeScript strict、`any` 禁止(外部ライブラリ境界での `unknown`→絞り込みは可)。
- モジュール依存方向: `parser → model → layout → render(toExcalidraw)`、`camera`/`ui` は `state` 経由。逆流禁止。
- React・JSX は `excal/host.tsx` のみに閉じる。他モジュールから React を import しない。Excalidraw API(updateScene等)へのアクセスは `camera/camera.ts` 経由に一本化する。
- DOM操作は `excal/` と `ui/` のみ。`parser/` `model/` `layout/`(elkjs呼出し除く)`render/toExcalidraw` は純関数で保ち、テスト可能にする。
- `@excalidraw/excalidraw` / `react` / `react-dom` のバージョンは固定(`^`なし)。更新する場合はT2-0bスパイクを再実行してから。
- 定数(閾値・色・寸法・タイミング)のマジックナンバー直書き禁止。すべて `constants.ts`。
- コメントは「なぜ」を書く。何をしているかはコードで表現する。

## 5. 検収について

各フェーズ完了時、指揮者(または検収担当エージェント)が完了条件を証拠ベースで確認する。差し戻し時は指摘に対する修正のみ行い、ついでの変更をしない。
