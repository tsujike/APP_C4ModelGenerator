# 実装フェーズ計画 — Mermarium(マーマリウム)

版 1.0 / 2026-07-18。各フェーズは前フェーズの完了条件をすべて満たしてから着手する。タスクの詳細分解は `docs/04_実装指示書.md`。

## フェーズ一覧

| Phase | 名称 | 成果 | 依存 |
|---|---|---|---|
| 0 | 足場 | Vite+TS+vitest が動く空アプリ | — |
| 1 | パーサ+統一モデル | テキスト→C4Model 変換(テスト済) | 0 |

## Phase 0 — 足場

- Vite + TypeScript(strict)+ vitest + ESLint/Prettier のプロジェクト初期化。
- `index.html` に画面骨格(ツールバー/エディタ/ビューワー/エラーパネルの空div、スプリッターは後回し)。
- `src/constants.ts` にズーム閾値・色などの定数枠を用意。

**完了条件**: `npm run dev` で骨格が表示される。`npm test`(ダミーテスト1件)緑。`npm run build` 成功。

## Phase 1 — パーサ+統一モデル

- `parser/`(splitBlocks / parseC4Block / parseClassBlock)と `model/build.ts` を設計書§4–5どおり実装。
- `samples/internet-banking.ts` に組込サンプル(設計書§5.4を4レベルフル構成に拡張したもの)を作成。
- ユニットテスト: 設計書§10の parser / build 系を網羅。サンプル→C4Model のスナップショットテスト。

**完了条件**: 全テスト緑。サンプルを parse して error 0件・意図した warning のみ。スナップショットが階層(Person1+System群 / Container / Component / Class)を正しく含む。

## Phase 2 — レイアウト+Excalidraw描画

- 冒頭に2つのスパイク(各半日上限): T2-0a elkjs入れ子レイアウト、T2-0b Excalidrawカメラ制御(updateSceneによるscroll/zoom適用・onChange監視)。**T2-0b不成立なら指揮者に報告し、設計書§12(自作SVG)への回帰判断を仰ぐ。**
- `model/project.ts`(エッジ射影・集約、設計書§6)+ユニットテスト。
- `layout/layout.ts`(elkjs)、`render/`(shapes / theme / toExcalidraw)、`excal/host.tsx`(Reactマウント、viewMode)。
- `camera/camera.ts`: onChange監視・zoom正規化・Fit(scrollToContent)・ズーム%表示。パン/ズーム操作自体はExcalidraw内蔵。
- この時点ではレベルは固定(L2をハードコード表示)。

**完了条件**: サンプルのL2図がExcalidraw上にC4配色で表示される(境界枠内にContainer群、Person/外部システムが枠外、エッジラベル付き)。Excalidraw内蔵のパン/ズームとFitボタンが動作。project のテスト緑。両スパイクの結果が PROGRESS.md に記録済み。

## Phase 3 — セマンティックズーム(最重要)

- `camera/lod.ts`: レベル判定(閾値+ヒステリシス、純関数)+ユニットテスト。
- レベル別レイアウトの遅延生成とキャッシュ。
- レベル切替: 要素+カメラ補正を1回のupdateSceneで同時適用するアンカー保存(設計書§8.3)。
- ツールバー: レベル表示、L1〜L4手動固定/AUTO切替。ビューワー内レベルバッジ。

**完了条件**: 受入基準1・2(要件§7)をブラウザで満たす。lod テスト緑。FR-5.7 は組込サンプルに含まれる「L3未定義のContainer」が L3 でも箱のまま表示されることで確認(サンプル改変は不要)。

## Phase 4 — エディタUX

- CodeMirror 6 導入(行番号・等幅)。300msデバウンスで再解析、カメラ維持(FR-1.3)。
- エラーパネル: ParseIssue を severity アイコン+行番号付きで表示、クリックで該当行へジャンプ。
- localStorage 自動保存/復元。サンプル読込メニュー(上書き確認付き)。
- エディタ/ビューワーのスプリッター。

**完了条件**: 受入基準3・4を満たす。エラー行クリックでエディタがスクロールする。

## Phase 5 — 仕上げ

- SVG/PNGエクスポート(FR-6)。
- 性能確認: 200ノード級の負荷サンプルで NFR-3 を計測、必要なら最適化(レイアウトのWeb Worker化は効果があるときのみ)。
- README.md(使い方・記法リファレンス・開発コマンド)。
- 全受入基準の最終検証。

**完了条件**: 受入基準1〜6すべて緑。README が存在し記法表を含む。

## 進捗管理

- 実装エージェントは各タスク完了時に `docs/PROGRESS.md` の該当チェックボックスを更新する(ファイルはPhase 0で作成。書式は 04_実装指示書 §2 参照)。
- フェーズ末には必ず「フェーズ完了条件の自己検証結果」を PROGRESS.md に1〜3行で記録する。

## リスクと備え

| リスク | 備え |
|---|---|
| elkjs の入れ子レイアウトが期待通りにならない | Phase 2 の最初に elkjs 単体の入れ子サンプルを動かすスパイク(T2-0a、半日上限)。不成立なら「境界ごとに個別レイアウト→親レイアウトに埋め込む」二段構えに切替(設計書の座標系は変更不要) |
| Excalidraw のカメラ制御(updateSceneでのscroll/zoom適用)が現行版で効かない・挙動が不安定 | Phase 2 冒頭のスパイク(T2-0b、半日上限)で検証。不成立なら設計書§12の自作SVGレンダラーに回帰(判断は指揮者)。影響はrender/camera層に閉じており、parser/model/layoutは無傷 |
| Excalidrawのバージョン更新でAPI挙動が変わる | package.jsonでバージョンを固定(^を付けない)。更新はスパイク再実行とセットでのみ行う |
| アンカー保存の体感が悪い | まず仕様通り実装し、受入時に指揮者が判断。調整は遷移時間と補間のみ(スコープを広げない) |
| CodeMirror 導入でビルド肥大 | 必要パッケージ(@codemirror/state, view, basic-setup相当)のみ。シンタックスハイライトは簡易(正規表現ベースのStreamLanguage)で十分 |
